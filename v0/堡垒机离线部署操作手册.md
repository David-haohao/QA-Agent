# 智能问答 Agent 堡垒机离线部署操作手册（Windows 小白版）

> 适用对象：Windows x64 堡垒机、不能访问互联网、但能访问内部 LLM API 的使用者。
>
> 目标：将本项目部署到堡垒机，使用项目内的 BGE-M3 与 BGE Reranker 模型构建新知识库，并通过浏览器访问智能问答页面。

## 一、先理解部署结构

本项目有三类模型或服务：

| 用途 | 运行位置 | 是否需要联网 |
| --- | --- | --- |
| LLM 大模型（生成回答） | 堡垒机可访问的内部 API | 需要能访问该内部地址 |
| BGE-M3（文档向量化） | 堡垒机本机，`local_models/bge-m3` | 不需要 |
| BGE Reranker（检索重排） | 堡垒机本机，`local_models/bge-reranker-v2-m3` | 不需要 |
| Qdrant 向量库 | 堡垒机本机，`kb_data/qdrant` | 不需要，也不需要 Docker |

因此，**LLM 使用 API 接入，不代表只复制代码就能运行**：首次部署仍需安装 Python 依赖、启动本地 BGE 服务、放入新文档并重建知识库。但如果内部 LLM API 兼容 OpenAI 接口，LLM 这一部分通常只需要改 `config.yaml`。

## 二、迁移前：在当前电脑准备要复制的内容

### 1. 需要复制的目录

将当前项目中的整个 `v0` 文件夹复制到 U 盘、共享盘或堡垒机允许的传输位置。下面两项**绝不能漏**：

- `v0/download/`：离线 Python 安装器和全部依赖包；
- `v0/local_models/`：本地嵌入和重排模型，约 4.41 GB。

为了让新环境干净，建议不要复制以下目录：

- `v0/.venv/`：旧电脑的 Python 环境；
- `v0/.offline-build-python31210/`、`v0/.offline-verify-venv/`、`v0/.offline-script-verify/`：本次离线包验证时产生的临时目录；
- `v0/kb_data/`：旧演示知识库数据；
- `v0/documents/`：旧演示文档。堡垒机上应放入新的正式文档。

如果您只能“整个文件夹原样复制”，也可以；但到堡垒机后，必须删除旧的 `.venv`、`kb_data` 和 `documents` 内容，再按本手册后续步骤操作。

### 2. 检查容量

建议堡垒机目标磁盘至少预留 **10 GB 可用空间**，用于：

- 离线安装包约 0.43 GB；
- 本地模型约 4.41 GB；
- Python 虚拟环境、Qdrant 数据、OCR 缓存和新文档。

## 三、在堡垒机放置项目

1. 登录堡垒机。
2. 在一个空间充足的位置创建项目目录。例如：`D:\QA-Agent`。
3. 将复制来的 `v0` 文件夹放进去，使最终路径类似：

   ```text
   D:\QA-Agent\v0\
   ```

4. 打开 `D:\QA-Agent\v0`，确认至少看得到：

   ```text
   download
   local_models
   config.example.yaml
   local_embedding_server.py
   build_qdrant.py
   run.py
   ```

## 四、离线安装 Python 和项目依赖

### 1. 打开 PowerShell

1. 按键盘 `Win + R`。
2. 输入 `powershell`。
3. 按回车。

> 后续所有命令都在 PowerShell 中执行。命令前面的 `PS ...>` 不需要输入。

### 2. 进入项目目录

假设您的项目位于 `D:\QA-Agent\v0`，复制并执行：

```powershell
cd D:\QA-Agent\v0
```

执行后，窗口开头应显示类似：

```text
PS D:\QA-Agent\v0>
```

### 3. 允许本次窗口运行安装脚本

执行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

这只对当前 PowerShell 窗口生效，关闭窗口后自动失效，不会永久修改堡垒机策略。

### 4. 校验离线安装包是否完整

执行：

```powershell
.\download\verify_offline.ps1 -SkipImportCheck
```

正确结果应包含：

```text
Verified 140 bundle files.
```

如出现 `Checksum mismatch` 或 `Checksum target is missing`，说明传输过程有文件损坏或遗漏。请重新复制整个 `download` 文件夹后再继续。

### 5. 执行离线安装

执行：

```powershell
.\download\install_offline.ps1
```

该步骤会自动完成：

1. 安装项目自带的 Python 3.12.10（不要求堡垒机预装 Python）；
2. 创建 `v0\.venv` 虚拟环境；
3. 从 `download\wheels` 安装全部依赖；
4. 执行 `pip check` 检查依赖关系。

看到以下内容表示安装成功：

```text
No broken requirements found.
Offline environment created successfully: ...\.venv\Scripts\python.exe
```

> 若提示“Refusing to overwrite the existing virtual environment”，说明复制时带来了旧 `.venv`。请确认这个旧环境可以不要后，删除 `v0\.venv` 文件夹，再重新执行本节第 5 步。

### 6. 安装后再验证一次

执行：

```powershell
.\download\verify_offline.ps1
```

应看到：

```text
Verified 140 bundle files.
Offline runtime imports verified
```

## 五、配置堡垒机 LLM API

### 1. 创建配置文件

项目默认读取 `config.yaml`。如果该文件不存在，执行：

```powershell
Copy-Item .\config.example.yaml .\config.yaml
```

然后用记事本打开：

```powershell
notepad .\config.yaml
```

### 2. 只修改 `llm:` 区块

找到文件顶部的 `llm:`，按堡垒机管理员提供的信息替换为类似内容：

```yaml
llm:
  api_key: "请填写管理员提供的API密钥"
  base_url: "http://10.0.0.20:8000/v1"
  model: "管理员提供的模型名称"
  provider: openai
  max_tokens: 4096
  temperature: 0.0
  timeout: 600
```

请特别注意：

- `api_key`：填写 API 密钥；如果 API 不需要密钥，请先向管理员确认是否使用非空占位值 `EMPTY`；
- `base_url`：填写 API 的**基础地址**，通常以 `/v1` 结尾；不要填写完整的 `/chat/completions` 地址；
- `model`：必须与管理员给出的模型标识完全一致；
- `provider: openai`：保持不变。

保存方式：记事本中点击“文件” → “保存”，然后关闭记事本。

### 3. 保持本地 BGE 配置不变

以下两个区块默认指向本机模型服务，**不要改成 LLM API 地址**：

```yaml
embeddings:
  model: bge-m3
  url: http://localhost:4000/v1/embeddings

reranker:
  model: bge-reranker-v2-m3
  url: http://localhost:4000/v1/rerank
```

这两个地址由本项目的 `local_embedding_server.py` 提供，读取的是 `local_models` 中已经随项目迁移的模型文件。

### 4. 更安全的密钥填写方式（可选）

如果不希望将真实 API 密钥写入 `config.yaml`，可将 `llm.api_key` 留空，并在每次启动前的 PowerShell 中执行：

```powershell
$env:QA_LLM_API_KEY = "请填写管理员提供的API密钥"
```

该变量只在当前 PowerShell 窗口和它启动的程序中有效。项目会自动优先使用它。

## 六、放入新的正式文档

1. 打开 `D:\QA-Agent\v0\documents` 文件夹。
2. 删除其中旧的演示文件。
3. 将新的正式文档复制到该文件夹。
4. 支持常见的 `.pdf`、`.docx`、`.doc`、`.xlsx`、`.xls`、`.txt`、`.md`、`.csv` 文件。

注意事项：

- 扫描版 PDF 会在本地执行 OCR，首次构建时间会较长；
- 旧格式 `.doc` 需要堡垒机安装 Microsoft Word，建议尽量转换为 `.docx`；
- 名称以 `._` 开头的文件是 macOS 附带的元数据文件，不是正式文档，请不要放入 `documents`；
- 新文档替换后必须重新构建知识库，不能复用旧演示向量库。

## 七、启动本地 BGE 模型服务

### 1. 打开第一个 PowerShell 窗口

进入项目目录：

```powershell
cd D:\QA-Agent\v0
```

启动本地嵌入和重排服务：

```powershell
.\.venv\Scripts\python.exe .\local_embedding_server.py
```

看到下列内容表示服务已启动：

```text
Uvicorn running on http://0.0.0.0:4000
```

**不要关闭这个窗口。**

### 2. 检查模型服务健康状态（可选但建议）

打开第二个 PowerShell 窗口，执行：

```powershell
Invoke-RestMethod http://127.0.0.1:4000/health
```

正确结果：

```text
status
------
ok
```

## 八、重建新的知识库

> 重建时 Web 服务必须处于停止状态；本地 Qdrant 是嵌入式数据库，同一时刻只能由一个进程访问。

在第二个 PowerShell 窗口中执行：

```powershell
cd D:\QA-Agent\v0
.\.venv\Scripts\python.exe .\build_qdrant.py
```

脚本会全量读取 `documents` 中的新文件，重新提取文本、生成 BGE-M3 向量、重建 Qdrant 和 BM25 索引。旧向量不会复用。

完成时应看到类似：

```text
重建完成：文档 100 份，文本块 2000 条
```

数字会随您的新文档数量变化。随后可查看重建记录：

```powershell
Get-Content .\kb_data\metadata.json -Encoding UTF8
```

若输出中有 `failed_files` 或 `skipped_files`，请把这些文件名交给文档提供方处理，不要把失败文件当作已入库。

## 九、启动 Web 问答页面

### 1. 保持 BGE 服务窗口不关闭

第一个 PowerShell 窗口中的 `local_embedding_server.py` 必须持续运行。

### 2. 在第二个窗口启动 Web

执行：

```powershell
.\.venv\Scripts\python.exe .\run.py web
```

正确结果包含：

```text
请在浏览器中打开: http://localhost:8080
```

### 3. 在浏览器验收

1. 打开浏览器；
2. 输入 `http://localhost:8080`；
3. 提问一个能够在新文档中找到答案的问题；
4. 检查回答是否带有对应文档来源。

如果要从堡垒机以外的电脑访问，需要网络管理员开放堡垒机的 `8080` 端口，并在浏览器访问：

```text
http://堡垒机IP地址:8080
```

## 十、常见问题排查

### 1. 提示端口 4000 或 8080 已被占用

错误中会出现 `WinError 10048`。先在 PowerShell 执行：

```powershell
Get-NetTCPConnection -LocalPort 4000,8080 -ErrorAction SilentlyContinue | Select-Object LocalPort,OwningProcess
```

记下对应的 `OwningProcess` 数字。确认该进程确实是旧的本项目服务后，再执行：

```powershell
Stop-Process -Id 上一步看到的数字
```

然后重新启动相应服务。不要随意结束不认识的进程。

### 2. `local_models` 不存在或模型加载报错

检查以下两个文件夹是否存在：

```powershell
Test-Path .\local_models\bge-m3
Test-Path .\local_models\bge-reranker-v2-m3
```

两行都应返回 `True`。若为 `False`，说明迁移时漏复制了模型目录。

### 3. Web 能打开但提问报 LLM 错误

依次检查：

1. `config.yaml` 中的 `base_url`、`api_key`、`model` 是否由管理员确认；
2. 堡垒机是否能访问该内部 API 地址；
3. API 是否支持 OpenAI 兼容的 `POST /v1/chat/completions`；
4. API 是否支持流式返回和工具调用（本项目 Agent 流程会使用它们）。

### 4. API 报 `enable_thinking` 参数不支持

当前项目会向 LLM 请求中附带 Qwen 风格的 `enable_thinking: true`。如果您的 API 是严格校验参数的非 Qwen 服务，可能拒绝该参数。

这种情况**不是只改 `config.yaml` 能解决的**。请保留报错信息并联系开发人员，对 `models/llm_client.py` 做一次兼容性调整；不要自行删除其他配置。

### 5. 重建知识库报 Qdrant 被占用

关闭正在运行的 Web 服务窗口（按 `Ctrl + C`），只保留本地 BGE 服务窗口，再重新执行：

```powershell
.\.venv\Scripts\python.exe .\build_qdrant.py
```

## 十一、日常启动顺序（以后每次使用）

以后不需要重复安装依赖，也不需要重复构建知识库。按以下顺序即可：

1. 打开 PowerShell 窗口 1，启动本地 BGE 服务：

   ```powershell
   cd D:\QA-Agent\v0
   .\.venv\Scripts\python.exe .\local_embedding_server.py
   ```

2. 打开 PowerShell 窗口 2，启动 Web：

   ```powershell
   cd D:\QA-Agent\v0
   .\.venv\Scripts\python.exe .\run.py web
   ```

3. 浏览器打开 `http://localhost:8080`。

只有在 `documents` 内容变更后，才按“第八章”重新构建知识库。
